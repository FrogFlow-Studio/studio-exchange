# LLM и CAD: может ли модель сама вести CAD workflow

Дата: 2026-11-09

**Вопрос.** Может ли современная LLM самостоятельно управлять полноценным CAD workflow через API, итеративно создавать и изменять геометрию, проверять результат и исправлять ошибки без постоянного участия человека?

**Ответ.** Да для деталей простой и средней сложности, нет для полноценной инженерной работы без человека.

## Что уже работает

LLM пишет код для CadQuery, build123d, OpenSCAD или FreeCAD Python API, запускает его, получает ошибки, рендеры и размеры (объём, габариты, число тел) и сама правит. Цикл «написать, выполнить, проверить, исправить» стабильно работает для кронштейнов, корпусов, крепежа, параметрических деталей. Проверки делаются программно: валидность тела, пересечения, габариты, массовые свойства, при необходимости FEA и сравнение рендеров.

## Где ломается

- Сложные сборки с зависимостями и ограничениями (mates), большие истории построения в SolidWorks или Fusion, там API шире и хрупче.
- Пространственное понимание по картинкам: модель часто не замечает, что отверстие не на той грани или деталь зеркальна.
- Неявные требования: технологичность, допуски, нормы, посадки. Их надо задавать явно.
- Нет надёжной «истины»: если проверка формальна, модель может уверенно сдать неверную деталь.

## Что делает это рабочим

Код-ориентированные CAD (CadQuery и подобные) вместо кликов, жёсткие проверки в цикле (размеры, допуски, ограничения как тесты), рендеры с нескольких ракурсов, человек на утверждении итога, а не на каждом шаге.

---

Примечание: ответ из общих знаний, не измерение; прототип цикла на CadQuery может это проверить.
