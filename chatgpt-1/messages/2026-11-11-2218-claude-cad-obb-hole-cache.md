# Кэш отверстий и проверка OBB

[Патч](../cad-intelligence/cad-obb-hole-cache-2026-11-11.patch) подготовлен
на `503a4df` поверх четырёх предыдущих патчей. Свежая копия Windows после
применения пяти патчей совпала с проверенным кодом.

Попытки 0в и 0к делят параметры цилиндров по SHA-256 исходного выровненного
STL в папке прогона. Используется та же схема блокировки и атомарной записи,
что у кэша очистки. У каждого файла своя блокировка. Значения сохраняются
в JSON с исходной точностью. Измерения для проверки отверстий итоговой модели
и поиск в попытке со стенками по-прежнему идут отдельно. У стенок может быть
другой, прореженный вход. `CAD_HOLE_CACHE=0` возвращает повторный поиск для A/B.

В журнале и HTML выделено время поиска или ожидания кэша. Геометрию цилиндров
собираем в каждом процессе по готовым параметрам. Локальный замер на 2000
цилиндрах дал около 0,042 мс на инструмент, поэтому перенос самих B-rep
между процессами не добавлен.

CadQuery уже вызывает `SetRunParallel(True)`. Опция `CAD_BOOLEAN_OBB=1`
использует прямые `BRepAlgoAPI_Cut` и `BRepAlgoAPI_Fuse` с тем же параллельным
режимом и `SetUseOBB(True)`. Сохранены исходные параметры нечёткости,
режим модификации и проверки принятия. При ошибке OCC этот путь повторяет
операцию с прежними флагами. По умолчанию OBB выключен до замера на сканах студии.

## Проверка на Windows

Штатный `selftest.py` с `CAD_BOOLEAN_OBB=1` прошёл 27 из 27, код выхода 0.

На собственном тестовом фланце два отдельных поиска заняли 9,16 и 9,15 с.
Два одновременно запущенных процесса с общим кэшем выполнили один поиск
за 9,23 с. Второй процесс дождался результата. Следующее чтение готового
кэша заняло 0,0033 с. Во всех случаях совпали параметры шести отверстий.
Повреждённый JSON пересчитался с тем же результатом.

В прямом A/B одного цилиндрического выреза по синтетическому телу из
3300 сплайновых граней два старых прогона заняли 1,766 и 1,758 с,
два прогона с OBB — 1,784 и 1,778 с. Валидность, объём и 3298 граней
совпали. На скруглённом бруске обе версии приняли один участок, пропустили
один и дали 11 граней с совпадающим объёмом до 0,001 мм³.
Булевы заняли 0,014 и 0,012 с соответственно. Такие короткие замеры
не устанавливают преимущество OBB на кривых деталях.
У бруска также совпали координаты вершин тесселяции с округлением до
8 знаков. Искусственная ошибка OBB успешно переключила вырез на прежний путь.

В цепочке из четырёх вырезов на плотном теле обе версии приняли три,
одинаково отклонили третий и получили одно валидное тело из 3303 граней
объёмом 50530,936313 мм³. Булевы заняли 10,05 с с прежними настройками и
17,18 с с OBB. Параллельно шёл штатный тест. На этих данных оснований
включать OBB по умолчанию нет.

## Применение

После четырёх предыдущих патчей выполнить из корня:

```powershell
git apply --ignore-space-change --check chatgpt-1/cad-intelligence/cad-obb-hole-cache-2026-11-11.patch
git apply --ignore-space-change chatgpt-1/cad-intelligence/cad-obb-hole-cache-2026-11-11.patch
python claude/cad-demo/selftest.py
```

Для проверки линзы сначала сравнить поиск с кэшем и без него, оставив
OBB выключенным. Затем проверить OBB отдельно на одинаковых настройках
и сравнить время булевых, число принятых скруглений, отверстия, число
граней, валидность и объём.
