# Сравнение и экспорт

[Патч](../cad-intelligence/cad-compare-export-2026-11-12.patch)
подготовлен на `c1ff553` поверх патчей 4–7. Патчи 1–3 уже в main.
На свежей Windows-копии эта цепочка воспроизвела проверенные исходники.
Компас включил патчи 4–6 в `dfdfef9`. На свежей копии этого коммита
достаточно патчей 7 и 8, и все файлы Python совпадают с проверенным вариантом.

- Выборка скана и KD-дерево вершин переиспользуются в пределах прогона.
  У эталона отдельный экземпляр. Для `n` и `seed` используются прежние
  генератор и порядок получения seed. До патча выборка тоже была
  детерминированной. Она пересчитывалась при каждом сравнении.
- Для расстояний «модель → скан» сохранены кандидаты из R-дерева,
  расчёт расстояний до треугольника и правило выбора между почти
  равными расстояниями из Trimesh 5.2. Минимумы вычисляются массивом,
  сортировка нужна лишь в случае близких кандидатов.
- Геометрический воркер в 0в и 0к пишет STEP. `cad_runner` читает этот
  же файл для замеров и STL и копирует его в папку результата. Раньше
  он экспортировал прочитанную форму повторно. Источник передачи
  задан в вызывающем коде только для этих двух геометрических попыток.
- CadQuery уже вызывает `BRepMesh_IncrementalMesh` параллельно.
  Тот же вызов и тот же бинарный STL writer теперь замеряются отдельно.
  Параметры линейного и углового допуска сохранены.
- Журнал и HTML показывают время загрузки STL, выборки, двух направлений
  расстояний, метрик и областей отклонений, отрисовки, чтения и записи STEP,
  его копирования, тесселяции и записи STL.

Для A/B `CAD_COMPARE_CACHE=0` выключает кэш и ускоренный расчёт расстояний.
`CAD_REUSE_WORKER_STEP=0` включает повторный экспорт STEP.

## Замеры на Windows

Штатный `selftest.py` прошёл 27 из 27 с включённым кэшем и
переиспользованием STEP, код выхода 0.

Синтетический скан с 81 920 треугольниками, три модели с разным совпадением.
Время сравнения сократилось с **3,64 до 2,58 с**. Направление «модель → скан»
заняло 1,43 → 0,87 с, выборка 0,282 → 0,166 с. Сама реализация знакового
расстояния «скан → модель» сохранена. Все поля сравнения, включая области,
массивы точек и расстояний, совпали точно. `within_tol_share` в трёх опытах
была 1,0000, 0,9753 и 0,7026, а p95 — 0,028, 0,281 и 0,390 мм.
Отдельно сверены исходный `compare.py` из Git с разными seed и размерами
выборки и правило близких расстояний на двух соседних треугольниках.

| Экспорт тела из 3300 сплайновых граней | Повторная запись | Копирование первого STEP |
| --- | ---: | ---: |
| STEP | 1,652 с | 0,014 с |
| Тесселяция STL | 0,763 с | 0,796 с |
| Запись STL | 0,006 с | 0,004 с |
| Полный CAD-процесс с замерами | 17,35 с | 16,23 с |

Полный процесс исходного раннера без новой детализации занял 16,07 с.
По одному замеру полное ускорение экспорта не установлено. Устранение
второй записи подтверждено. STL совпал побайтно с исходным раннером.
STEP в обоих вариантах перечитался как одно валидное тело с 3300 гранями
и объёмом 51361,191149 мм³.

В сквозной проверке с синтетическим телом и заранее подготовленным
ответом геометрического воркера обе настройки выбрали 0в с 100% в
допуске и одинаковым STL. В HTML появились новые времена. Включённый
режим прошёл через передачу STEP от воркера, выключенный через
повторный экспорт.

## Применение

```powershell
git apply --ignore-space-change --check chatgpt-1/cad-intelligence/cad-compare-export-2026-11-12.patch
git apply --ignore-space-change chatgpt-1/cad-intelligence/cad-compare-export-2026-11-12.patch
python claude/cad-demo/selftest.py
```

Замер на кронштейне сравнить при одинаковых настройках и одинаковом
порядке попыток. Измерения здесь относятся к синтетике.
