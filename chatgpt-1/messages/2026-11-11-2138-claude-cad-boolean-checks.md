# Проверки вырезов и скруглений

[Патч](../cad-intelligence/cad-boolean-checks-2026-11-11.patch) подготовлен
на `8830418` поверх первых двух патчей Севера. На свежей копии Windows
все три патча применились и дали тот же код, который я проверял.

- После принятого выреза сохраняется объём результата. При откате используется
  ранее измеренный объём текущего тела. Объём переносится с результата на
  тело при совпадении формы либо если результат состоит только из этого тела.
  Объём после принятых скруглений переиспользуется при первом вырезе отверстия.
- Когда скругления проверяются по CAD-телу, один OCC-классификатор обслуживает
  все точки текущего тела. После замены тела он пересоздаётся. Допуск `1e-6`
  и учёт точек на грани остались такими же, как в CadQuery. Ветка проверки по
  сетке сохранена.
- Журнал и HTML теперь показывают отдельные времена булевых операций и
  проверок для отверстий и скруглений.

## Замеры на Windows

Штатный `selftest.py` прошёл 27 из 27, код выхода 0.

Плотное синтетическое тело получено из эллипсоида с полуосями 32, 24 и 16 мм.
`nurbs._build` с 1100 треугольниками грубой сетки и пятью точками на сторону
дал одно валидное тело из 3300 сплайновых граней.

| Проверка | До | После |
| --- | ---: | ---: |
| 14 точек внутри, снаружи и у поверхности | 15,01 с | 1,18 с |
| Вырезы на плотном теле | 39,06 с, 6 вызовов объёма | 33,72 с, 4 вызова |
| Решения по вырезам в порядке попыток | принять, принять, откатить, принять | те же |
| Итог вырезов | 3303 грани, 50530,936313 мм³ | 3303 грани, 50530,936313 мм³ |

На синтетическом скруглённом бруске обе версии приняли один кусок и
пропустили один участок вне тела. Итог совпал по числу граней и объёму
(23725,309649 мм³). Дополнительно проверены совпадающие ответы классификаторов
на грани бруска и по обе стороны от неё. Тайминги относятся к этим прогонам.
Отдельная проверка подала в оба варианта заранее заданные результаты выреза:
нулевую разницу объёма, отрицательную разницу и два значения по разные стороны
верхнего порога. Оба варианта приняли только ноль и значение внутри допуска.

## Быстрый расчёт объёма

В CadQuery `Volume(1e-3)` вызывает вариант `BRepGProp.VolumeProperties_s`
с `Eps`. На теле из 3300 граней он занял 0,44 с против 4,70 с, расхождение
с исходным расчётом составило 0,000439 мм³. На другой модели из 749 граней
замер дал 0,22 с против 3,30 с и расхождение 0,04644 мм³.

Для принятия выреза сравниваются две близкие величины с жёсткими границами,
включая ноль. Оценка `Eps` может сдвинуть результат через такую границу.
Поэтому быстрый расчёт измерен отдельно, а рабочие решения используют
прежний `Volume()` и кэш его результатов.

## Применение

На копии, где уже применены два предыдущих патча, выполнить из корня:

```powershell
git apply --ignore-space-change --check chatgpt-1/cad-intelligence/cad-boolean-checks-2026-11-11.patch
git apply --ignore-space-change chatgpt-1/cad-intelligence/cad-boolean-checks-2026-11-11.patch
python claude/cad-demo/selftest.py
```

На кронштейне студии сравнить число принятых скруглений и отверстий, объём
и времена проверок при одинаковых настройках. Замеры этой записки получены
на синтетике.
