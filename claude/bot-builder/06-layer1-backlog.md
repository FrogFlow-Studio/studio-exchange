# 06. Слой 1 (ядро): задачи

Порядок сверху вниз. Статус: ○ не начато, ✱ в работе, ✓ готово. Обновляется по ходу работы.

## A. Основа репозитория
- ○ A1. Монорепозиторий TypeScript: `packages/spec` (формат), `packages/engine` (движок), `packages/generator` (ИИ), `apps/studio` (веб и мини-приложение), `apps/api` (вебхуки). Линт, prettier, vitest, команда `npm run check`.
- ○ A2. CLAUDE.md с правилами репозитория, CI-скрипт проверки локально.
- ○ A3. Конфиг окружения в одном месте, подставные значения для тестов.

## B. Формат спецификации бота
- ○ B1. Схема (zod): бот, языки, данные (таблицы), шаги, кнопки, блоки, расписания.
- ○ B2. Статическая проверка: тупики, переходы в никуда, пустые тексты, все языки заполнены, недостижимые шаги.
- ○ B3. Версии спецификации, сравнение версий (diff).

## C. Движок
- ○ C1. Разбор входящего апдейта Telegram, состояние разговора, исполнение шага.
- ○ C2. Блоки общения: сообщение, медиа, кнопки, меню, форма, выбор из таблицы, переход к оператору.
- ○ C3. Блоки данных: таблицы бота, карточка клиента, теги.
- ○ C4. Блок записи: услуги, сотрудники, график, слоты, бронь, перенос, отмена.
- ○ C5. Блок магазина: каталог, варианты, корзина, заказ, статусы.
- ○ C6. Анкета и квиз с ветвлением, итог, передача владельцу.
- ○ C7. Платный доступ в канал или чат: срок, продление, удаление.
- ○ C8. Планировщик: напоминания, отложенные шаги, окончание доступа.
- ○ C9. Отправка в Telegram через абстракцию (тестовый и настоящий клиент), тайм-ауты, без повторов отправки, которая могла дойти.

## D. Тестовый стенд
- ○ D1. Симулятор Telegram: разговор с ботом по спецификации без сети.
- ○ D2. Формат тестового разговора (шаги пользователя и ожидаемые ответы), прогон набора.
