# Ступени гладкого тела

[Патч](../cad-intelligence/cad-nurbs-stages-2026-11-11.patch) подготовлен
на `dfc2bd4` поверх трёх предыдущих патчей. Проверил применение всей
цепочки на свежей копии Windows.

В строку «время по этапам» для каждой ступени добавлены раскладка, проекция,
подгонка, поиск потерь, замены граней, MakeFace, сшивка, сборка тела,
`near_share` и `cover_share`. Сборка и покрытие показывают подэтапы.
Их время входит в родительские этапы.

## Отказ и ускорение

- До сшивки можно посчитать тот же `near_share` по тем же точкам будущих граней.
  При наличии выбранного тела ступень пропускает сшивку, если её оценка
  ниже `GOAL` и не выше оценки уже выбранного тела. В таком случае прежний
  каскад не мог принять ступень или выбрать её как лучшую.
- `_lossy` оценивает промежуточную сетку до замены участков. Эта оценка
  не ограничивает сверху покрытие готового тела, поэтому я не использовал её
  как причину отказа. Ступени, которые могут выиграть или пройти порог,
  по-прежнему строятся и проходят полную проверку.
- В проекции координаты округляются массивом в том же порядке. В поиске
  потерь и покрытии точка уже в допуске, если рядом есть вершина самой сетки
  с запасом на разрешение равенств в Trimesh. Остальные точки проверяются
  прежним поиском ближайшего треугольника. Выборка, тесселяция и пороги сохранены.
- Для сборки от 500 граней включён параллельный режим того же анализатора OCC.
  Точный объём для определения ориентации оставлен. В отдельном замере на
  теле из 3300 граней проверка валидности ускорилась с 0,52 до 0,24 с.

`CAD_NURBS_FAST=0` оставляет замеры, но выключает эти изменения для A/B.
Правила времени и список `STEPS` сохранены. При попадании в общий предел
времени ускорение может дать возможность проверить дополнительную ступень.

## Первые замеры

Штатный `selftest.py` на Windows прошёл 27 из 27, код выхода 0.

| Синтетический скан | До | После | Результат обеих версий |
| --- | ---: | ---: | --- |
| Эллипсоид, допуск 0,3 мм | 19,82 с | 19,17 с | ступень 1, 750 граней, покрытие 1,000 |
| Волнистый тор, допуск 0,3 мм | 21,09 с | 18,31 с | ступень 1, 750 граней, покрытие 1,000 |
| Волнистый тор, допуск 0,04 мм | 24,21 с | 22,82 с | ступень 1, 750 граней, покрытие 0,994167 |
| Волнистый тор, допуск 0,008 мм | 144,31 с | 146,18 с | ступень 4, 4467 граней, диагностическое покрытие 0,895567 |

На последнем входе обе версии отклонили первые три ступени. Их покрытия
совпали по отдельности: 0,736067, 0,786333 и 0,891067. Ступень 4 прошла
по прежнему критерию интерполяции `near_share=1,0`. Покрытие 0,895567
измерено отдельно на итоговом теле. При сравнении совпали выбранная
ступень, число граней, все доступные оценки и решения по ступеням.

На плотном тесте суммарная проекция сократилась с 22,82 до 15,69 с,
проверка валидности с 2,30 до 1,17 с. Полное ускорение не подтверждено
этим замером. Штатные тесты шли параллельно с частью этих прогонов, так
что общие времена чувствительны к нагрузке. Проверка знака объёма
заняла 31–34 с суммарно и осталась самым дорогим подэтапом.

На торе при 0,3 мм проекция заняла 3,52 → 2,07 с, поиск потерь 2,68 → 0,14 с.
Сшивка в этих опытах занимала меньше 0,4 с. Внутри сборки основное время
уходит на точную проверку ориентации по объёму. В тесте с заранее заданными
оценками вторая ступень пропустила сшивку, обе версии выбрали третью
с 920 гранями и оценкой 0,995. Сопоставил быстрый признак попадания
с точным расстоянием на 4000 точках при трёх допусках.

## Применение

На копии, где уже применены три предыдущих патча, выполнить из корня:

```powershell
git apply --ignore-space-change --check chatgpt-1/cad-intelligence/cad-nurbs-stages-2026-11-11.patch
git apply --ignore-space-change chatgpt-1/cad-intelligence/cad-nurbs-stages-2026-11-11.patch
python claude/cad-demo/selftest.py
```

На кронштейне и линзе сравнить `CAD_NURBS_FAST=0` и `CAD_NURBS_FAST=1`
при одинаковом кэше, очистке, допусках и режиме фонового запуска.
