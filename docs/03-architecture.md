# 03. Архитектура

## Главный принцип

ИИ не пишет программу. Он пишет **описание бота** (спецификацию) в нашем формате. Спецификацию исполняет наш движок, одинаковый для всех ботов. Так ошибка ИИ — это ошибка логики, которую ловят проверки, а не сломанный код.

## Части системы

1. **Бот-менеджер Botaqan.** Создан один раз вручную в BotFather, у него включено управление ботами. Через него пользователи создают своих ботов (Managed Bots), он получает токены.
2. **Студия:** чат с ИИ, предпросмотр, админка. Веб плюс мини-приложение Telegram.
3. **Генератор:** ИИ превращает описание пользователя в спецификацию.
4. **Проверяльщик:** статическая проверка спецификации и автотесты разговорами.
5. **Движок (runtime):** принимает вебхуки всех ботов, читает спецификацию и состояние разговора, отвечает.
6. **Хранилище:** спецификации и их версии, данные ботов (записи, заказы, заявки), состояние разговоров.
7. **Платежи:** вебхуки эквайера, Telegram Stars.
8. **Планировщик:** напоминания, рассылки, окончание доступа.

## Формат спецификации (набросок)

```yaml
bot:
  name: "Салон Айгерим"
  languages: [ru, kk]
data:
  services: { fields: [name, price, duration_min] }
  bookings: { fields: [service, client, slot, status, paid] }
flows:
  start:
    message: { ru: "Здравствуйте! Записать вас?", kk: "Сәлеметсіз бе! Жазайын ба?" }
    buttons: [ { text: { ru: "Записаться" }, go: choose_service } ]
  choose_service:
    pick_from: services
    go: choose_slot
  choose_slot:
    block: booking.slots          # готовый блок
    go: pay
  pay:
    block: payment.prepay
    params: { percent: 30 }
    on_success: done
schedules:
  - block: booking.reminder
    params: { before: "24h" }
```

Готовые блоки: сообщения, кнопки, анкеты, выбор из таблицы, запись на слоты, корзина, оплата, доступ в канал, уведомление владельцу, рассылка, напоминание, ИИ-ответ на свободный вопрос по описанию бизнеса.

## Генерация и проверка

1. ИИ собирает спецификацию по описанию и ответам на уточняющие вопросы.
2. Статическая проверка: схема, тупики, кнопки в никуда, переходы без выхода, пустые тексты, все языки заполнены.
3. ИИ пишет 20–30 тестовых разговоров по описанию пользователя, «пользователь-тестер» проходит их на движке в песочнице.
4. Ошибки уходят обратно в генератор, до 3 кругов исправления.
5. Публикация только после зелёной проверки. Каждая публикация это новая версия, можно откатить.

Опыт ENVERIQ: золотые диалоги и сценарии из реальных переписок, их тот же подход.

## Создание бота (Managed Bots)

1. Студия показывает кнопку или ссылку `t.me/newbot/<менеджер>/<имя>` (формат по aiHola, сверить с официальной документацией).
2. Пользователь подтверждает в Telegram.
3. Менеджер получает событие, берёт токен (`bots.exportBotToken`), сохраняет его зашифрованным.
4. Botaqan ставит вебхук на движок, задаёт описание, команды, кнопку мини-приложения.

Открытые вопросы: лимит ботов на один менеджер, отзыв доступа менеджера пользователем, что происходит при удалении бота в BotFather.

## Стек [предложение]

Как в ENVERIQ, чтобы переиспользовать опыт: TypeScript, Supabase (Postgres, RLS по владельцу бота), Vercel или Fly для движка (вебхуки, постоянная нагрузка), Claude для генерации. Отдельный репозиторий и отдельная база, не общая с ENVERIQ.

## Безопасность

- Токены ботов шифруются, в логи не попадают.
- Данные каждого бота отделены от других (RLS).
- Модерация описаний и спецификаций: мошенничество, казино, запрещённые товары.
- Ограничения на рассылки, чтобы ботов не банил Telegram.
