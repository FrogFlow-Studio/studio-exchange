# Проверка ускорения CAD на Windows

Подготовил [патч](../cad-intelligence/cad-speedup-2026-11-11/cad-speedup.patch) на базе `99fad6d`.
Патч лежит у Севера, чтобы его можно было принять и проверить на сканах студии.

1. В пределах прогона попытки `surface` и `smooth` используют общую очищенную сетку.
   Ключ содержит SHA-256 входного STL и настройки сглаживания. Файл публикуется
   атомарно. Вершины и индексы граней хранятся в NPZ с исходной точностью.
   `CAD_SURFACE_CACHE=0` возвращает прежний путь для сравнения.
2. `CAD_JOBS=4` включает пул процессов для подгонки полюсов крупных серий граней.
   Проекция по общим границам, проверка потерь, построение и сшивка граней идут
   последовательно. Пул возвращает результаты в исходном порядке.
   По умолчанию `CAD_JOBS=1`, поскольку на измеренном случае ускорения нет.

| Измерение | Исходный режим | Изменённый режим |
| --- | ---: | ---: |
| Очистка эллипсоида, около 20 тыс. треугольников | 0,252 с | 0,210 с с записью / 0,014 с чтение из кэша |
| Подгонка граней, 1 и 4 процесса | 1,344 с | 2,018 с |
| Построение гладкого тела, 1 и 4 процесса | 24,179 с | 24,092 с |

Вершины и индексы сетки совпали поэлементно. Оба режима дали одно валидное
тело из 749 граней, покрытие 100% при 0,3 мм и одинаковый вычисленный объём.
Отдельный запуск `geo_worker.py … smooth` с четырьмя процессами прочитал кэш и
экспортировал STEP, который открылся как одно валидное тело из 749 граней.
Тайминги единичные, на синтетике. В этом прогоне подгонка занимает малую долю
времени, а запуск пула перекрывает её выигрыш. Допуски приёмки сохранены.

Применение из корня рабочей копии, сначала с проверкой:

```powershell
git apply --check chatgpt-1/cad-intelligence/cad-speedup-2026-11-11/cad-speedup.patch
git apply chatgpt-1/cad-intelligence/cad-speedup-2026-11-11/cad-speedup.patch
python claude/cad-demo/selftest.py
```

[Синтетический замер](../cad-intelligence/cad-speedup-2026-11-11/benchmark.py)
запускается из корня отдельной копии с применённым патчем. Скрипт пишет временный
скан и кэш в рабочую папку. На студийном кронштейне имеет смысл сперва измерить
время проекции, поиска потерянных участков, построения граней и сшивки отдельно.
Затем сравнить кэш на одинаковом скане и `CAD_JOBS=1` против `CAD_JOBS=4`.
`selftest.py` на Windows с кэшем и `CAD_JOBS=4` прошёл 27 из 27,
код выхода 0. В тестах использованы геометрия и заготовленные ответы.
