## 81а. Демо

Пути 0к/0п/0с уже стартуют параллельно. Проверки отверстий теперь переиспользуют сечения одного скана между попытками. Пороговые сравнения 0п/0с считают только покрытие скан → модель с прежним seed, выборкой, допуском и округлением. Для таблицы сравнения с эталоном покрытие победителя переиспользуется, для остальных попыток вычисляется только нужное направление. Полные двусторонние карты остаются у обычной проверки результата.

`demo.py` сохраняет `timings.json` рядом с отчётом, с временами основного процесса и воркеров. На тех же двух моделях фланца отдельный прогон проверок отверстий дал 5,68 → 0,89 с при идентичных списках замечаний.

Профилирование запускалось на Windows в режиме `geometric`, с прежним методом контуров. До изменений использовался `a1fc50e`, после — правки Севера поверх `b05d354`, где уже есть кэш сечений и объёма от Компаса. Замеры воркеров перекрываются между собой. Прогоны делили ресурсы с другими проверками, поэтому таблица показывает фактическое время этих запусков. Вклад одной правки проверялся отдельно на одинаковых моделях.

| Этап | Infiniti, было → стало, с | Фланец, было → стало, с |
| --- | ---: | ---: |
| Весь запуск под cProfile | 572,81 → 498,52 | 83,62 → 100,71 |
| От начала обработки до формирования HTML, округлено в отчёте | 560 → 480 | 57 → 69 |
| Загрузка и подготовка скана | 0,6 → 1,0 | 3,4 → 4,8 |
| 0к, в воркере | 83,71 → 138,16 | не запускался |
| 0п, в воркере | 178,42 → 249,05 | не запускался |
| 0с, в воркере | 523,79 → 454,51 | не запускался |
| Вызовы `compare.py`, суммарно по cProfile | 85,06 → 84,50 | 9,52 → 6,22 |
| Сравнения при 0,3 мм, внутри предыдущей строки | 41,05 → 35,27 | не запускались |
| Обязательные проверки геометрии | <0,01 → <0,01 | 4,71 → 0,76 |
| Макрос SolidWorks | <0,01 → <0,01 | около 5 по журналу → 3,47 |
| Формирование HTML | 4,11 → 3,63 | 0,47 → 0,60 |

На Infiniti победил 0с с 363 гранями, одним валидным телом и покрытием 100,0% при округлении в журнале. На фланце победил 0ж с 12 гранями, одним валидным телом и покрытием 97,8%. Для каждой детали SHA-256 итогового STL до и после совпал. Макрос на Infiniti не сформировался в обоих прогонах. На фланце макрос сформировался, проверка эталона дала 100,0%.

На трёх неизменных моделях Infiniti покрытие при 0,3 мм совпало до четырёх десятичных знаков доли. Для 0к доля 0,9146 (20,24 → 18,95 с), 0п — 0,9882 (1,42 → 0,77 с), 0с — 0,9998 (3,16 → 2,12 с). Дорогая часть сравнения по-прежнему в вычислении расстояний скан → модель на сложной сетке. Полный локальный `selftest.py` завершился с кодом 0.

Команда для повторного прогона из `claude/cad-demo`. Для фланца добавить `--truth ПУТЬ_К_ЭТАЛОНУ`.

```powershell
python -m cProfile -o profile.prof demo.py ПУТЬ_К_STL --mode geometric --no-open --out output
```

## 81б. Контуры

`SEC_FAST=1` включает сборку XY-контуров из отрезков пересечения, polygonize и чётность вложенности. Неоднозначные сечения передаются прежнему обработчику. Переключатель по умолчанию выключен. Стенд `benchmark_81_sections.py` принимает пути к STL и выравнивает их как демо.

| Деталь | Высоты | Откат на высотах | Было, с | Стало, с | Максимум симметрической разницы, мм² |
| --- | ---: | ---: | ---: | ---: | ---: |
| Infiniti | 67 | 0 | 0,432 | 0,297 | 0,000000722 |
| Фланец | 127 | 127 | 5,690 | 6,510 | 0 |
| Втулка | 202 | 201 | 27,867 | 34,202 | 0,000000002 |
| Кронштейн | 131 | 131 | 6,056 | 10,358 | 0 |

Количество контуров и распределение числа отверстий по контурам совпали на каждой высоте. Время «стало» включает проверку быстрого метода и повторный расчёт прежним методом на уровнях с откатом. Ускорение воспроизведено на кнопке (1,46×). На трёх повреждённых стендах частые невалидные кольца и разрывы дают проигрыш.
