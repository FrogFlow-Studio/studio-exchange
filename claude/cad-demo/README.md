# Демо: скан повреждённой детали → CAD-модель (Компас, 09.11.2026)

Цель: к 15.11 показать владельцу студии рабочий цикл на его задаче: пришла сломанная
деталь, её отсканировали, а программа строит черновик модели целой детали (STEP для
CAD, STL для печати), который проверяет инженер, и показывает, насколько модель
совпала с уцелевшей частью скана. Ранний прототип: проверен на наших искусственных
деталях, на сканах студии ещё нет.

## Как это работает

```
скан STL ─► 1. проверка и замеры (геометрия, без ИИ)
            плоскости, сечения, отверстия, контуры, выравнивание
         ─► 2. ИИ пишет модель на CadQuery (Python), восстанавливая скол по замыслу
         ─► 3. модель строится в отдельном процессе, проверяется валидность тела
         ─► 4. сравнение со сканом: где совпало, где модели не хватает материала,
               где скол, что достроено
         ─► отчёт уходит обратно ИИ, он правит модель (до 5 попыток)
         ─► лучшая попытка: model.step (SolidWorks), model.stl (печать), report.html
```

Шаги 1, 3 и 4 — обычная геометрия, их ИИ не подменяет: цифры в отчёте посчитаны, а
не «сказаны» моделью. ИИ отвечает только за замысел: что это за деталь и как её построить.

## Запуск

Один раз: поставить Python 3.10–3.12 (Windows: с python.org, галочка «Add to PATH»),
потом `install.bat` (Windows) или `pip install -r requirements.txt` (Mac).

Показ: `start.bat` / `./start.sh`. Откроется страница в браузере: перетащить скан
(или «взять тестовую деталь»), написать, что сломано, «Построить модель». Видно
журнал попыток, в конце отчёт со скачиванием STEP/STL. Страница работает на этом
компьютере, интернет не нужен (кроме вызова ИИ). Файл скана целиком никуда не
отправляется; если включён ИИ, ему уходят замеры (числа), заметка, фото, если оно
приложено, и ответы на его запросы к сетке (сечения, точки, лучи — куски геометрии скана).

Ключ ИИ (без него включается режим без ИИ, см. ниже):
Windows `set ANTHROPIC_API_KEY=...` перед `start.bat`, Mac `export ANTHROPIC_API_KEY=...`.

Из командной строки: `run.bat` / `./run.sh [скан.stl] ["что сломано"]`, или полностью
`python demo.py скан.stl --notes "..." [--image фото.jpg] [--iters 5] [--tol 0.3]`.
Результаты: `out/<время>/report.html`, `model.step`, `model.stl`.

## Режимы — в отчёте всегда написан режим

Всегда сначала идёт **попытка 0 — алгоритм без ИИ** (`geometric.py`): слои по сечениям
скана, отверстия, дорисовка того, что проверяемо геометрией (недостающее отверстие в
повторе, полная окружность по дуге, зеркальная половина симметричного контура). Он
работает без ключа и без интернета. ИИ потом строит модель «по замыслу» и правит её;
в итог идёт лучшая из всех попыток.

| Режим | Когда | Что в отчёте |
|---|---|---|
| `geometric` | нет ключа (по умолчанию) | «БЕЗ ИИ: геометрический алгоритм» — настоящий расчёт |
| `anthropic` / `openai` | есть ключ | «живой прогон, <модель>» |
| `replay` | показ без интернета: `--mode replay --replay out/<прогон>/llm_log.json` | «ПОВТОР записанного прогона» |
| `scripted` | только проверка конвейера: `--mode scripted` | «БЕЗ ИИ: заготовленные ответы» |

**Как ИИ видит скан** (`--ai-input`, по умолчанию `tools`): ИИ сам опрашивает сетку
инструментами из `scan_tools.py` — сечение по X/Y/Z на любой высоте, луч (толщины, глубины,
есть ли материал), точки с нормалями в области, вписать плоскость, вписать окружность (и по
дуге скола), ближайшая точка поверхности. Картинок нет. Не больше `--max-tool-calls` (30)
вызовов на попытку; прогон останавливается, если оценка расхода выше `--budget-usd` ($1).
Все запросы и расход пишутся в `llm_log.json`. `--ai-input sheet` — старый вариант: лист
замеров и картинка видов скана. `--no-geometric` — ИИ без попытки 0 (для сравнения).

Записанный или заготовленный прогон нельзя выдавать за живой: отчёт это пишет крупно.

## Файлы

- `geometric.py` — построение без ИИ (попытка 0); `app.py` — страница в браузере; `demo.py` — цикл и отчёт; `scan_analysis.py` — замеры; `compare.py` — сравнение;
  `cad_runner.py` — запуск кода модели; `llm.py` — запросы к ИИ и подсказка.
- `selftest.py` — самопроверка одной командой (около минуты, без ИИ): замеры трёх деталей, испорченные сканы (повёрнут, в метрах, с дырами, с мусором), полный цикл.
- `make_test_bushing.py` — третья тестовая деталь: втулка с буртом и шпоночным пазом, отколот сектор бурта (`samples/bushing_*`).
- `make_test_flange.py` — вторая тестовая деталь: фланец, отломан край вместе с одним из шести отверстий (`samples/flange_*`).
- `make_test_part.py` — тестовая деталь: кронштейн, у которого мы сами отломали угол
  и добавили шум сканера. `samples/bracket_scan.stl` — «скан», `bracket_truth.step` —
  целая деталь (её ИИ не видит, она нужна только для проверки в конце).
- `samples/scripted_<деталь>.json` — заготовленные ответы для режима без ИИ (их написал
  разработчик, а не ИИ).
- `vendor/` — three.js 0.160 (MIT) для 3D в отчёте.
- `PLAN.md` — план по дням и честное состояние. `DEMO_SCRIPT.md` — сценарий показа.

Код, который пишет ИИ, исполняется на компьютере в отдельном процессе с тайм-аутом,
лимитом памяти (кроме Windows) и без ключей в окружении. Это не песочница: для демо на
своём ноутбуке приемлемо, для пилота с файлами клиента нужна изоляция (контейнер без сети).

## Кандидат StepCAD (необязательно)

StepCAD — открытая ИИ-модель (веса Apache-2.0), пишет программу CadQuery по скану. Программа
берёт её результат, только если он точнее остальных кандидатов. Код StepCAD в репозиторий не входит:

```
git clone https://github.com/ghadinehme/StepCAD
set STEPCAD_DIR=путь\к\StepCAD      (Linux: export STEPCAD_DIR=...)
pip install torch transformers safetensors huggingface_hub pebble pyarrow manifold3d libigl pymeshlab scikit-learn
```

При видеокарте NVIDIA кандидат включается сам (`--stepcad auto`), на процессоре — по `--stepcad on`
(около 15 минут на деталь). Веса (~3,3 ГБ) скачиваются при первом запуске. Сильная сторона —
механические детали из простых форм; кривые корпуса StepCAD не умеет.
