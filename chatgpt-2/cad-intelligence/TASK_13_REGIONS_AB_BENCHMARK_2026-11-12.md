# Северу: задача 13. Полный A/B-бенчмарк регионального маршрута

**Приоритет:** высокий  
**Тип:** производительность / качество / регрессионная проверка  
**Зависимость:** выполнять после интеграции и фиксации стабильной версии этапа Б. Не сравнивать разные или незавершённые состояния кода.

## Цель

Измерить, даёт ли новый маршрут с `CAD_REGIONS=1` реальный выигрыш по времени, точности, устойчивости и ресурсам на полном конвейере CAD Intelligence по сравнению со стабильным старым маршрутом.

Главный объект измерения — результат всей обработки, а не скорость отдельного модуля сегментации.

## Сравниваемые варианты

**A. Старый маршрут:** зафиксированный стабильный commit и штатные настройки без регионального режима.

**B. Новый маршрут:** один явно записанный commit со всеми принятыми изменениями этапа Б и включённым `CAD_REGIONS=1`.

До запуска указать SHA обоих вариантов, конфигурацию, версии зависимостей и параметры. Не менять код между A/B-прогонами.

## Набор деталей

- тестовый фланец;
- тестовая втулка;
- линза студии;
- кронштейн студии;
- Hyundai.

Если какая-либо модель недоступна или не может быть обработана одним из вариантов, зафиксировать это как отдельный результат, а не исключать молча.

## Метрики

Для каждого прогона измерить:

1. Полное время обработки от входного скана до готового STEP.
2. Время стадий: очистка, анализ, сегментация, огрубление, построение поверхностей, сборка B-rep, валидация и экспорт.
3. Пиковое потребление RAM.
4. Количество граней, рёбер и тел.
5. Покрытие и двустороннее отклонение поверхности.
6. Валидность, замкнутость и связность B-rep.
7. Размер STEP.
8. Количество неудачных операций и откатов.
9. Для деталей с пригодным эталоном — точность восстановленных инженерных элементов по результатам задачи 12.

## Правила эксперимента

- Использовать одинаковые исходные сканы и параметры.
- Использовать одинаковое оборудование и программное окружение.
- Зафиксировать плотность измерительной тесселяции, стратегию выборки, seed и допуски.
- Выполнить минимум два повтора, предпочтительно три; отдельно указать холодный и прогретый запуск, если кэш влияет на результат.
- Не смешивать время отдельной стадии с полным временем конвейера.
- Не скрывать случаи, когда новый маршрут медленнее, менее точен или не завершает обработку.
- Не снижать критерии качества ради ускорения.
- Сравнивать только артефакты, созданные указанными SHA.

## Критерии приёмки

- Есть запускаемый скрипт `benchmark_regions_full.py`.
- Есть JSON с сырыми результатами каждого прогона.
- Есть сравнительная таблица A/B по каждой детали.
- Отдельно показаны скорость, память, геометрическое качество и топология.
- Указаны SHA, конфигурации, параметры и ограничения эксперимента.
- Сделан вывод, где новый маршрут выигрывает, где проигрывает и почему.
- Если новый маршрут проигрывает, предложены конкретные причины и следующие эксперименты, без автоматического изменения production-настроек.

## Ожидаемые артефакты

- `benchmark_regions_full.py`;
- конфигурация воспроизводимого запуска;
- JSON с результатами;
- Markdown-отчёт A/B.

**Важно:** не включать региональный режим по умолчанию на основании одного удачного теста. Решение о production-default остаётся за Компасом после проверки результатов.
